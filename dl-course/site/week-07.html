Sequence Models: RNNs, LSTMs, and the Road to Attention

How to model data that arrives in order. Recurrent networks, backpropagation through time and why gradients vanish or explode, LSTM and GRU gating, sequence-to-sequence learning with teacher forcing and beam search, and the attention mechanism that made recurrence optional.

Learning objectives

By the end of this week you should be able to:

  • Classify sequence problems (one-to-many, many-to-one, many-to-many) and formulate language modeling as next-token prediction, including cross-entropy, bits per character and perplexity.
  • Write the equations of a vanilla RNN, unroll it, and implement the forward pass from scratch in NumPy and with torch.nn.RNN, with correct tensor shapes.
  • Derive backpropagation through time, show how the gradient is a product of Jacobians, and use the spectral radius to explain vanishing and exploding gradients. Apply truncated BPTT and gradient clipping.
  • Explain every gate of an LSTM and a GRU, and argue from the cell-state recursion why gating improves gradient flow.
  • Build bidirectional and stacked recurrent networks and know when a bidirectional model is not allowed (autoregressive generation).
  • Implement an encoder-decoder with teacher forcing, discuss exposure bias, and implement greedy and beam-search decoding.
  • Derive Bahdanau (additive) and Luong (multiplicative) attention, and read an attention heatmap as a soft alignment.
  • Compare recurrent models with 1D convolutional and temporal convolutional networks for translation, speech and time-series forecasting.

So far every input in this course had a fixed size: a vector of features, an image of 224×224224\times224224×224 pixels. Much of the world is not like that. A sentence has a variable number of words, an audio clip a variable number of samples, a patient record a variable number of visits, a stock price an ever-growing history. The order matters ("dog bites man" is not "man bites dog"), the length varies, and the relevant information may be separated by hundreds of steps.

This week is the story of how neural networks learned to handle such data. It begins with the recurrent neural network, an idea that is conceptually simple (apply the same function at every time step, carrying a memory forward) and mathematically revealing, because training it exposes the vanishing and exploding gradient problem in its purest form. We then follow the chain of fixes: gating (LSTM, GRU), reading in both directions, stacking, encoder-decoder models, and finally attention, the mechanism that lets a decoder look back at every input position directly. Week 9 will take attention and remove the recurrence entirely, giving the Transformer. Understanding why people needed attention is the best way to understand why the Transformer looks the way it does.

If you have not already, skim Week 2 (backpropagation as reverse-mode autodiff) and Week 3 (vanishing gradients and clipping); this week builds directly on both.

Sequential data and the task zoo

A sequence is an ordered list x1,x2,…,xT\boldsymbol{x}_1,\boldsymbol{x}_2,\dots,\boldsymbol{x}_Tx1​,x2​,…,xT​ whose length TTT may differ from example to example. Each element xt\boldsymbol{x}_txt​ might be a one-hot vector for a character, an index into a vocabulary of words, a frame of audio features, or a vector of sensor measurements. Three properties make sequences different from the fixed-size inputs of previous weeks:

  1. Variable length. A model must accept T=3T=3T=3 and T=3000T=3000T=3000 with the same parameters.
  2. Order dependence. Permuting the elements changes the meaning, so a model cannot treat the input as a bag.
  3. Long-range dependencies. The right output at step ttt may depend on something seen at step t−200t-200t−200: the subject of a sentence determines verb agreement many words later, a closing bracket must match an opening one far earlier.

Problems differ in how input and output sequences relate. It helps to name the common patterns, because each leads to a different wiring of the same recurrent building block.

  • One-to-many. One input, a sequence out. Image captioning feeds one image embedding into a recurrent decoder that emits words. Music or text generation from a seed also fits.
  • Many-to-one. A sequence in, a single label out. Sentiment classification, spam detection, classifying a time series (is this ECG abnormal?). You read the final hidden state, or pool over all of them.
  • Many-to-many, aligned. One output per input step, same length. Part-of-speech tagging, named-entity recognition, frame-by-frame speech labeling, per-step forecasting.
  • Many-to-many, unaligned (sequence-to-sequence). Input and output lengths differ and no step-by-step correspondence exists: machine translation, summarization, speech recognition. This needs the encoder-decoder design of a later section.

Language modeling as the canonical sequence task

A language model assigns a probability to a sequence of tokens. Using the chain rule of probability (no approximation yet),

p(w1,…,wT)=∏t=1Tp(wt∣w1,…,wt−1).p(w_1,\dots,w_T)=\prod_{t=1}^{T}p(w_t\mid w_1,\dots,w_{t-1}).p(w1​,…,wT​)=t=1∏T​p(wt​∣w1​,…,wt−1​).

Every factor is the probability of the next token given the whole past. An autoregressive model parameterizes exactly these conditionals with a network that reads the prefix w<tw_{<t}w<t​ and outputs a distribution over the vocabulary of size VVV. Training is plain supervised learning: the input at step ttt is wt−1w_{t-1}wt−1​ (plus the hidden state that summarizes the older past), the target is wtw_twt​. Nobody has to label anything, which is why language modeling scales: any text is training data. This is the same objective that later powers GPT-style models (Week 10).

Before neural networks, the standard approach was the nnn-gram model, which truncates the history to the last n−1n-1n−1 tokens and estimates p(wt∣wt−n+1:t−1)p(w_t\mid w_{t-n+1:t-1})p(wt​∣wt−n+1:t−1​) by counting. It fails in two ways. The table of counts grows as VnV^{n}Vn, and most nnn-grams are never observed, so you need elaborate smoothing. And it cannot use context beyond n−1n-1n−1 tokens, however informative. A recurrent network replaces the explicit count table with a fixed-size learned state, so the number of parameters does not grow with the context length.

Cross-entropy, bits per character and perplexity

We train by maximizing the log-likelihood of the data, equivalently by minimizing the average cross-entropy over tokens:

L=−1T∑t=1Tlog⁡pθ(wt∣w<t).\mathcal{L}=-\frac{1}{T}\sum_{t=1}^{T}\log p_{\boldsymbol{\theta}}(w_t\mid w_{<t}).L=−T1​t=1∑T​logpθ​(wt​∣w<t​).

Reporting conventions differ by community. In nats (natural log) this is the loss PyTorch's cross_entropy returns. Character-level models are usually quoted in bits per character (BPC), the same quantity with log⁡2\log_2log2​, so BPC=L/ln⁡2\text{BPC}=\mathcal{L}/\ln 2BPC=L/ln2. Word-level models are quoted as perplexity:

PPL=exp⁡(L)=(∏t=1Tp(wt∣w<t))−1/T.\mathrm{PPL}=\exp(\mathcal{L})=\Big(\prod_{t=1}^T p(w_t\mid w_{<t})\Big)^{-1/T}.PPL=exp(L)=(t=1∏T​p(wt​∣w<t​))−1/T.

Perplexity has a clean interpretation: it is the effective branching factor. A model that is uniformly uncertain among kkk equally likely next tokens has L=ln⁡k\mathcal{L}=\ln kL=lnk and perplexity exactly kkk. A model with perplexity 50 is, on average, as unsure as if it were choosing uniformly among 50 words. A uniform model over a vocabulary of VVV words has perplexity VVV; that is the baseline you must beat, and a perfect model has perplexity 1.

Perplexities are only comparable under identical tokenization

A character-level model with 1.2 BPC and a word-level model with perplexity 100 cannot be compared directly, and two word-level models with different vocabularies or different handling of unknown words cannot either: the per-token loss is averaged over different units. Convert to a common unit (for example bits per byte of the raw text) before comparing. This matters again in Week 8, where subword tokenizers change the number of tokens per sentence.

Sanity check you should always run before training: with VVV outputs and random initialization the initial loss should be close to ln⁡V\ln VlnV (for 65 characters, about 4.17 nats). If it is much larger your logits are too big; if the loss never leaves ln⁡V\ln VlnV your model is ignoring its input.

The recurrent neural network

Here is the central idea. Instead of a function of the whole input, learn a function that consumes one element at a time and updates a fixed-size summary of everything seen so far, the hidden state ht∈Rd\boldsymbol{h}_t\in\R^{d}ht​∈Rd. The same function (the same weights) is applied at every step.

The vanilla (Elman) recurrent network is

ht=ϕ ⁣(Wxhxt+Whhht−1+bh),ot=Whyht+by,y^t=softmax⁡(ot),\boldsymbol{h}_t=\phi\!\left(\mathbf{W}_{xh}\boldsymbol{x}_t+\mathbf{W}_{hh}\boldsymbol{h}_{t-1}+\boldsymbol{b}_h\right),\qquad \boldsymbol{o}_t=\mathbf{W}_{hy}\boldsymbol{h}_t+\boldsymbol{b}_y,\qquad \hat{\boldsymbol{y}}_t=\softmax(\boldsymbol{o}_t),ht​=ϕ(Wxh​xt​+Whh​ht−1​+bh​),ot​=Why​ht​+by​,y^​t​=softmax(ot​),

with xt∈Rm\boldsymbol{x}_t\in\R^{m}xt​∈Rm, Wxh∈Rd×m\mathbf{W}_{xh}\in\R^{d\times m}Wxh​∈Rd×m, Whh∈Rd×d\mathbf{W}_{hh}\in\R^{d\times d}Whh​∈Rd×d, Why∈RV×d\mathbf{W}_{hy}\in\R^{V\times d}Why​∈RV×d, nonlinearity ϕ\phiϕ (usually tanh⁡\tanhtanh) and initial state h0\boldsymbol{h}_0h0​ (zeros, or learned). Read the first equation as: the new state is a squashed mixture of the current input and the previous state. The hidden state is the network's only memory.

Two observations organize everything that follows.

Parameter sharing across time. The weights Wxh,Whh,Why\mathbf{W}_{xh},\mathbf{W}_{hh},\mathbf{W}_{hy}Wxh​,Whh​,Why​ do not depend on ttt. This is the temporal analogue of the convolution's weight sharing in Week 5: it encodes the assumption that the rule for updating memory is the same at every position, it lets the model handle any length, and it keeps the parameter count independent of TTT. A model that saw "the cat sat" at positions 1 to 3 automatically knows what to do with "the cat sat" at positions 51 to 53.

Unrolled, an RNN is a very deep network. A sequence of length 1000 produces a computation graph with 1000 layers, each using the same matrix Whh\mathbf{W}_{hh}Whh​. Week 3 taught you what products of many matrices do to gradients. Recurrence is that problem with no escape hatch: you cannot choose a shallower network without ignoring part of the sequence.

Why not just feed a window to an MLP?

A fixed-window MLP (concatenate the last nnn embeddings and classify) is the neural version of the nnn-gram. It has the same defect: context size is frozen into the architecture, and the weights for position t−3t-3t−3 are unrelated to the weights for t−2t-2t−2, so nothing learned about "a noun two words back" transfers across positions. The RNN's state can, in principle, carry information from arbitrarily far back, and its weights are shared. Whether it does in practice is the subject of the next sections.

Computing an RNN forward pass from scratch

The following NumPy implementation makes the shapes explicit. It runs a batch of BBB sequences of length TTT through a tanh RNN, and is the code we will differentiate by hand in the BPTT section.

pythonrnn_numpy.py
import numpy as np

rng = np.random.default_rng(0)
B, T, m, d, V = 4, 6, 10, 16, 10     # batch, steps, input dim, hidden dim, vocab/output dim

# Parameters (small random init; see the BPTT section for why scale matters)
Wxh = rng.normal(0, 1 / np.sqrt(m), (d, m))
Whh = rng.normal(0, 1 / np.sqrt(d), (d, d))
Why = rng.normal(0, 1 / np.sqrt(d), (V, d))
bh, by = np.zeros(d), np.zeros(V)

def rnn_forward(x, h0):
    """x: (B, T, m). Returns logits (B, T, V), hidden states (B, T+1, d)."""
    hs = [h0]
    logits = []
    for t in range(T):
        a = x[:, t] @ Wxh.T + hs[-1] @ Whh.T + bh   # (B, d) pre-activation
        h = np.tanh(a)                               # (B, d) new state
        hs.append(h)
        logits.append(h @ Why.T + by)                # (B, V) per-step output
    return np.stack(logits, axis=1), np.stack(hs, axis=1)

x = rng.normal(size=(B, T, m))
logits, hs = rnn_forward(x, np.zeros((B, d)))
print(logits.shape, hs.shape)        # (4, 6, 10) (4, 7, 16)
print(np.abs(hs).max())              # tanh keeps the state in (-1, 1)

Where recurrence came from

Recurrent connections were studied long before deep learning. Hopfield (1982) analysed symmetric recurrent networks as associative memories. Jeffrey Elman (1990, "Finding Structure in Time") trained a simple recurrent network with a hidden-state copy-back loop on small linguistic tasks and showed it learned word-class structure; that architecture is the "Elman RNN" above. Jordan networks (1986) fed the output back instead. The training algorithm, backpropagation through time, was described in the late 1980s (Werbos 1988 and Rumelhart, Hinton and Williams 1986 for the unrolling view). The vanishing gradient diagnosis arrived in 1991 to 1994 (Hochreiter's diploma thesis, then Bengio, Simard and Frasconi), and the LSTM (Hochreiter and Schmidhuber, 1997) was the answer.

Backpropagation through time

Training an RNN means computing ∂L/∂θ\partial\mathcal{L}/\partial\boldsymbol{\theta}∂L/∂θ for the shared parameters. Because unrolling gives an ordinary acyclic graph, you do not need a new algorithm: apply reverse-mode autodiff (Week 2) to the unrolled graph and sum the contributions from every time step where a weight was used. This is backpropagation through time (BPTT). The derivation is worth doing in full, because the structure of the result explains the main pathology of recurrent networks.

Setup and notation

Use the pre-activation form. Let at=Wxhxt+Whhht−1+bh\boldsymbol{a}_t=\mathbf{W}_{xh}\boldsymbol{x}_t+\mathbf{W}_{hh}\boldsymbol{h}_{t-1}+\boldsymbol{b}_hat​=Wxh​xt​+Whh​ht−1​+bh​ and ht=tanh⁡(at)\boldsymbol{h}_t=\tanh(\boldsymbol{a}_t)ht​=tanh(at​), with per-step loss Lt=ℓ(y^t,yt)\mathcal{L}_t=\ell(\hat{\boldsymbol{y}}_t,y_t)Lt​=ℓ(y^​t​,yt​) and total loss L=∑t=1TLt\mathcal{L}=\sum_{t=1}^{T}\mathcal{L}_tL=∑t=1T​Lt​ (sum or mean, a constant factor). Write δt=∂L/∂at\boldsymbol{\delta}_t=\partial\mathcal{L}/\partial\boldsymbol{a}_tδt​=∂L/∂at​ for the gradient at the pre-activation; it is the quantity that gets propagated backwards.

For softmax cross-entropy the gradient of Lt\mathcal{L}_tLt​ with respect to the logits is o\boldsymbol{o}o-space error et=y^t−yt\boldsymbol{e}_t=\hat{\boldsymbol{y}}_t-\boldsymbol{y}_tet​=y^​t​−yt​ (predicted probabilities minus the one-hot target), exactly as in Week 2. The state ht\boldsymbol{h}_tht​ influences the loss in two ways: directly through its own output Lt\mathcal{L}_tLt​, and indirectly through the next state ht+1\boldsymbol{h}_{t+1}ht+1​, which feeds every later loss. Multiplying through by the activation derivative gives a recursion for δt\boldsymbol{\delta}_tδt​: δt=Dt ⁣(Why⊤et+Whh⊤δt+1),δT+1=0.\boldsymbol{\delta}_t=\mathbf{D}_t\!\left(\mathbf{W}_{hy}^\top\boldsymbol{e}_t+\mathbf{W}_{hh}^\top\boldsymbol{\delta}_{t+1}\right),\qquad \boldsymbol{\delta}_{T+1}=\mathbf{0}.δt​=Dt​(Why⊤​et​+Whh⊤​δt+1​),δT+1​=0.

Parameter gradients. Each weight is used at every step, so its gradient is a sum over time of the local outer products: ∂L∂Whh=∑t=1Tδtht−1⊤,∂L∂Wxh=∑t=1Tδtxt⊤,∂L∂bh=∑t=1Tδt.\frac{\partial\mathcal{L}}{\partial\mathbf{W}_{hh}}=\sum_{t=1}^{T}\boldsymbol{\delta}_t\boldsymbol{h}_{t-1}^\top,\quad \frac{\partial\mathcal{L}}{\partial\mathbf{W}_{xh}}=\sum_{t=1}^{T}\boldsymbol{\delta}_t\boldsymbol{x}_t^\top,\quad \frac{\partial\mathcal{L}}{\partial\boldsymbol{b}_h}=\sum_{t=1}^{T}\boldsymbol{\delta}_t .∂Whh​∂L​=t=1∑T​δt​ht−1⊤​,∂Wxh​∂L​=t=1∑T​δt​xt⊤​,∂bh​∂L​=t=1∑T​δt​.

Unfold the recursion. The contribution of the loss at step ttt to the gradient with respect to an earlier state hk\boldsymbol{h}_khk​ (k<tk<tk<t) is

∂Lt∂hk=(∂ht∂hk) ⁣⊤∂Lt∂ht,∂ht∂hk=∏j=k+1tJj=∏j=k+1tDjWhh.(1)\frac{\partial\mathcal{L}_t}{\partial\boldsymbol{h}_k}=\left(\frac{\partial\boldsymbol{h}_t}{\partial\boldsymbol{h}_k}\right)^{\!\top}\frac{\partial\mathcal{L}_t}{\partial\boldsymbol{h}_t}, \qquad \frac{\partial\boldsymbol{h}_t}{\partial\boldsymbol{h}_k}=\prod_{j=k+1}^{t}\mathbf{J}_j=\prod_{j=k+1}^{t}\mathbf{D}_j\mathbf{W}_{hh}. \tag{1}∂hk​∂Lt​​=(∂hk​∂ht​​)⊤∂ht​∂Lt​​,∂hk​∂ht​​=j=k+1∏t​Jj​=j=k+1∏t​Dj​Whh​.(1)

This product of t−kt-kt−k Jacobians is the whole story. It is what lets the loss at step ttt teach an input at step kkk ("this early word should have been remembered"), and it is also exactly where learning breaks down.

A NumPy BPTT implementation, with a gradient check

Implementing the recursion once, by hand, and verifying it numerically is the best way to make it concrete. The code below does a char-level RNN step with BPTT and checks one parameter's gradient against central finite differences.

pythonbptt_numpy.py
import numpy as np

rng = np.random.default_rng(1)
V, d, T = 5, 8, 7                       # vocab, hidden size, sequence length
Wxh = rng.normal(0, 0.3, (d, V)); Whh = rng.normal(0, 0.3, (d, d))
Why = rng.normal(0, 0.3, (V, d)); bh = np.zeros(d); by = np.zeros(V)
xs = rng.integers(0, V, T); ys = rng.integers(0, V, T)   # integer-coded input/target tokens

def loss_and_grads(Wxh, Whh, Why, bh, by, h0=None):
    h = np.zeros(d) if h0 is None else h0
    hs, ps, loss = {-1: h}, {}, 0.0
    for t in range(T):                                    # forward
        hs[t] = np.tanh(Wxh[:, xs[t]] + Whh @ hs[t - 1] + bh)   # one-hot x: column lookup
        o = Why @ hs[t] + by
        p = np.exp(o - o.max()); ps[t] = p / p.sum()
        loss += -np.log(ps[t][ys[t]])
    dWxh, dWhh, dWhy = np.zeros_like(Wxh), np.zeros_like(Whh), np.zeros_like(Why)
    dbh, dby = np.zeros_like(bh), np.zeros_like(by)
    delta_next = np.zeros(d)                              # delta_{T+1} = 0
    for t in reversed(range(T)):                          # backward through time
        e = ps[t].copy(); e[ys[t]] -= 1                   # softmax-CE gradient wrt logits
        dWhy += np.outer(e, hs[t]); dby += e
        delta = (1 - hs[t] ** 2) * (Why.T @ e + Whh.T @ delta_next)   # recursion from the derivation
        dWhh += np.outer(delta, hs[t - 1]); dWxh[:, xs[t]] += delta; dbh += delta
        delta_next = delta
    return loss, (dWxh, dWhh, dWhy, dbh, dby)

loss, (dWxh, dWhh, dWhy, dbh, dby) = loss_and_grads(Wxh, Whh, Why, bh, by)

# Central finite differences on a few entries of Whh
eps = 1e-5
for (i, j) in [(0, 0), (3, 5), (7, 2)]:
    Wp = Whh.copy(); Wp[i, j] += eps
    Wm = Whh.copy(); Wm[i, j] -= eps
    num = (loss_and_grads(Wxh, Wp, Why, bh, by)[0] - loss_and_grads(Wxh, Wm, Why, bh, by)[0]) / (2 * eps)
    print(f"dWhh[{i},{j}]  analytic {dWhh[i, j]: .8f}  numeric {num: .8f}")

Vanishing and exploding gradients in time

Look again at the product in equation (1). To understand its behavior, start with the simplest case: a linear RNN with ϕ=identity\phi=\mathrm{identity}ϕ=identity, where Jj=Whh\mathbf{J}_j=\mathbf{W}_{hh}Jj​=Whh​ for every jjj. Then ∂ht/∂hk=Whh t−k\partial\boldsymbol{h}_t/\partial\boldsymbol{h}_k=\mathbf{W}_{hh}^{\,t-k}∂ht​/∂hk​=Whht−k​. Suppose Whh\mathbf{W}_{hh}Whh​ is diagonalizable, Whh=QΛQ−1\mathbf{W}_{hh}=\mathbf{Q}\boldsymbol{\Lambda}\mathbf{Q}^{-1}Whh​=QΛQ−1. Then

Whh n=QΛnQ−1,\mathbf{W}_{hh}^{\,n}=\mathbf{Q}\boldsymbol{\Lambda}^{n}\mathbf{Q}^{-1},Whhn​=QΛnQ−1,

and each eigen-direction is scaled by λi n\lambda_i^{\,n}λin​. Bounding the gradient with the spectral norm

The spectral radius gives the asymptotic rate; a clean bound uses the induced 2-norm. Since ∥AB∥2≤∥A∥2∥B∥2\|\mathbf{A}\mathbf{B}\|_2\le\|\mathbf{A}\|_2\|\mathbf{B}\|_2∥AB∥2​≤∥A∥2​∥B∥2​ and the diagonal matrix Dj\mathbf{D}_jDj​ has ∥Dj∥2=max⁡i∣ϕ′(aj,i)∣≤γ\|\mathbf{D}_j\|_2=\max_i|\phi'(a_{j,i})|\le\gamma∥Dj​∥2​=maxi​∣ϕ′(aj,i​)∣≤γ (γ=1\gamma=1γ=1 for tanh, γ=1/4\gamma=1/4γ=1/4 for the sigmoid), ∥∂ht∂hk∥2≤∏j=k+1t∥Dj∥2 ∥Whh∥2≤(γ σmax⁡(Whh))t−k.\left\|\frac{\partial\boldsymbol{h}_t}{\partial\boldsymbol{h}_k}\right\|_2\le\prod_{j=k+1}^{t}\|\mathbf{D}_j\|_2\,\|\mathbf{W}_{hh}\|_2\le\left(\gamma\,\sigma_{\max}(\mathbf{W}_{hh})\right)^{t-k}.​∂hk​∂ht​​​2​≤j=k+1∏t​∥Dj​∥2​∥Whh​∥2​≤(γσmax​(Whh​))t−k. This is the Pascanu, Mikolov and Bengio (2013) argument. For tanh (γ=1\gamma=1γ=1) it means that a recurrent matrix with largest singular value below 1 guarantees vanishing gradients. The converse does not hold: σmax⁡>1\sigma_{\max}>1σmax​>1 does not guarantee explosion (the bound is an upper bound; the product can still shrink if the large singular directions do not align between steps), but ρ(Whh)>1\rho(\mathbf{W}_{hh})>1ρ(Whh​)>1 is a necessary condition for exploding gradients in the linear case, and in the nonlinear case it gives growth along the directions where the activation is not saturated.

Two caveats make the real picture richer than "ρ<1\rho<1ρ<1 vanishes, ρ>1\rho>1ρ>1 explodes".

  1. Saturation changes the picture. With tanh, Dj\mathbf{D}_jDj​ has entries ≤1\le 1≤1 and often much smaller: when a unit saturates (∣h∣≈1|h|\approx1∣h∣≈1), 1−h2≈01-h^2\approx01−h2≈0 and that unit's gradient is killed. So a tanh RNN with ρ\rhoρ moderately above 1 often does not explode, because saturation pulls the effective gain back down, as the measurements below show.
  2. Vanishing and exploding are two sides of one coin. The product of nnn random-ish matrices has singular values that spread out exponentially (a fact from random matrix theory: Lyapunov exponents). You almost never get a clean ρn\rho^nρn; some directions blow up while others vanish. Practically, the network sits on the edge: it has a narrow band of weight scales where gradients are usable.

Why long dependencies are structurally hard

Think of the gradient as a message sent backward through nnn relays. Each relay multiplies the message by a gain. A gain slightly below 1 at every relay erases the message; slightly above 1 amplifies the message and the noise alike. Training only needs a sum of many such messages with different path lengths, so the short paths (a few steps) dominate the sum when gains are below 1. The network learns easily from recent context and effectively cannot learn from distant context. Notice that this is a learning problem, not a representational one: an RNN can store information for hundreds of steps (with the right weights, e.g. Whh=I\mathbf{W}_{hh}=\mathbf{I}Whh​=I copies the state forever), but gradient descent from a standard initialization cannot find those weights.

Remedies, short of changing the architecture

Several tricks mitigate the problem without gating:

  • Gradient clipping for the exploding side. Rescale the gradient when its norm exceeds a threshold ccc: g←g⋅min⁡(1,c/∥g∥)\boldsymbol{g}\leftarrow\boldsymbol{g}\cdot\min(1,c/\|\boldsymbol{g}\|)g←g⋅min(1,c/∥g∥). It keeps the direction and limits the step. This is cheap, almost universally used for RNNs, and was popularized for recurrent nets by Pascanu et al. (2013). It does nothing for vanishing gradients.
  • Careful initialization. Initialize Whh\mathbf{W}_{hh}Whh​ as an orthogonal matrix (all singular values exactly 1, nn.init.orthogonal_), or as the identity (the "IRNN" of Le, Jaitly and Hinton, 2015, with ReLU units). This puts the network at ρ=1\rho=1ρ=1 at the start, at the cost of no longer being stable once trained.
  • Regularize the gradient norm or the spectral norm (soft constraints on Whh\mathbf{W}_{hh}Whh​), or constrain it exactly to the orthogonal group (unitary RNNs, Arjovsky, Shah and Bengio, 2016). These help on synthetic memory tasks but have not displaced gating in practice.
  • Skip connections through time and ReLU-like activations. The idea of giving gradients an additive route is exactly what the LSTM does, next.

A measured example of clipping

To see clipping in action we trained the NumPy RNN from the BPTT section (48 hidden units, sequence chunks of 25 characters, learning rate 3.0, plain SGD) on a tiny repetitive corpus, twice with identical initialization: once unclipped and once with the global gradient norm clipped to 5. The learning rate is deliberately aggressive, which is when exploding gradients show up.

Implementing clipping in PyTorch takes one line between backward() and step(). The function returns the pre-clipping norm, which is a useful quantity to log: a sudden spike in it is the earliest warning that training is about to diverge.

pythonclip_torch.py
import torch
import torch.nn as nn

opt.step()

Truncated BPTT

Full BPTT on a long sequence (a book of a million characters) is impossible in memory: it must store every intermediate state until the backward pass. Truncated BPTT (TBPTT) cuts the sequence into chunks of length KKK and treats each chunk as a separate training example, with one crucial twist: the hidden state at the end of chunk jjj is carried forward as the initial state of chunk j+1j+1j+1, but detached from the graph, so no gradient flows across the chunk boundary.

text
chunk 1:  x_1 ... x_K          h_0 = 0          loss, backward within chunk
chunk 2:  x_{K+1} ... x_{2K}   h_0 = h_K.detach()   loss, backward within chunk
chunk 3:  ...

What this does and does not do:

  • The forward pass still uses information from before the chunk (the carried state), so the model can in principle exploit long context at inference time.
  • The backward pass cannot assign credit across the boundary, so dependencies longer than KKK steps are never learned from gradients. KKK is a hard cap on the credit-assignment horizon. Typical values for language modeling are K=35K=35K=35 to 200200200.
  • Memory and time per update scale with KKK rather than with the sequence length, and the batch of chunks must be arranged so that row bbb of consecutive minibatches continues the same stream (otherwise the carried state is meaningless).

In PyTorch the idiom is h = h.detach() after every optimizer step (for an LSTM, detach both hhh and ccc). Forgetting it has two symptoms: memory grows without bound until you hit an out-of-memory error, and PyTorch raises "Trying to backward through the graph a second time". We will use it in the lab.

LSTM: long short-term memory

The diagnosis in the previous section suggests the cure. The trouble is that the state is rewritten multiplicatively by a matrix and squashed at every step, so information and gradient both pass through a long chain of transformations. What if the memory had a route that was updated additively, with a gain near 1 by default? Hochreiter and Schmidhuber (1997) proposed exactly this, calling it the constant error carousel, and wrapped it in learned gates that decide what to write, keep and read.

The LSTM keeps two vectors per layer: the cell state ct∈Rd\boldsymbol{c}_t\in\R^dct​∈Rd (long-term memory, the conveyor belt in the figure) and the hidden state ht∈Rd\boldsymbol{h}_t\in\R^dht​∈Rd (the short-term output that other layers see). Every gate, explained

Gates are soft switches. A sigmoid output lies in (0,1)(0,1)(0,1) and is applied elementwise, so each coordinate of the memory gets its own dial between "completely closed" (0) and "completely open" (1). Gates are learned functions of the context, not fixed numbers: the network decides at every step, per unit, how much to erase and write.

  • Forget gate ft\boldsymbol{f}_tft​ (erase). Multiplies the old cell state. f=1f=1f=1 keeps a memory cell unchanged, f=0f=0f=0 wipes it. It lets the network reset memory at natural boundaries (a new sentence, a closed bracket). It was not in the original 1997 LSTM, which had a constant carry of 1 and so could never erase; Gers, Schmidhuber and Cummins (2000) added it, and it turned out to be the most important gate (Greff et al. 2017, "LSTM: a search space odyssey", found forget gate and output activation to be the critical components).
  • Input gate it\boldsymbol{i}_tit​ and candidate c~t\tilde{\boldsymbol{c}}_tc~t​ (write). The candidate proposes new content in (−1,1)(-1,1)(−1,1); the input gate decides how much of it to admit. Separating "what to write" from "whether to write" lets the model ignore irrelevant inputs: i≈0i\approx0i≈0 makes the cell blind to the current token.
  • Cell state ct\boldsymbol{c}_tct​ (memory). The additive update ct=ft⊙ct−1+it⊙c~t\boldsymbol{c}_t=\boldsymbol{f}_t\odot\boldsymbol{c}_{t-1}+\boldsymbol{i}_t\odot\tilde{\boldsymbol{c}}_tct​=ft​⊙ct−1​+it​⊙c~t​ is the heart of the design. The old memory is scaled and added to, never pushed through a weight matrix and a squashing nonlinearity.
  • Output gate ot\boldsymbol{o}_tot​ (read). The cell may store information that is not needed right now. The output gate chooses which coordinates of tanh⁡(ct)\tanh(\boldsymbol{c}_t)tanh(ct​) to expose to the rest of the network and to the next step's gates. The tanh⁡\tanhtanh bounds the exposed value even when the cell grows large.

Because everything is elementwise except the four matrix products, you can implement all four affine maps as one matrix multiplication of size 4d×(d+m)4d\times(d+m)4d×(d+m) and split the result. That is what nn.LSTM does; the parameter count of a single layer is 4 (d m+d2+2d)4\,(d\,m+d^2+2d)4(dm+d2+2d) in PyTorch's layout (input weights, recurrent weights, two bias vectors).

Why gating fixes (most of) the gradient problem

Differentiate the cell recursion with respect to the previous cell state. Holding the gates fixed (they also depend on ht−1\boldsymbol{h}_{t-1}ht−1​, which we will come back to),

∂ct∂ct−1=diag⁡(ft)+(terms through the gates).\frac{\partial\boldsymbol{c}_t}{\partial\boldsymbol{c}_{t-1}}=\diag(\boldsymbol{f}_t)+\text{(terms through the gates)} .∂ct−1​∂ct​​=diag(ft​)+(terms through the gates).

Compare with the vanilla RNN Jacobian DtWhh\mathbf{D}_t\mathbf{W}_{hh}Dt​Whh​, a dense matrix that rotates and squashes. The LSTM's direct path is diagonal with entries ft,i∈(0,1)f_{t,i}\in(0,1)ft,i​∈(0,1) that the network controls. Over nnn steps the direct path contributes

∂ct∂ct−n≈diag⁡(∏j=t−n+1tfj).\frac{\partial\boldsymbol{c}_t}{\partial\boldsymbol{c}_{t-n}}\approx\diag\Big(\prod_{j=t-n+1}^{t}\boldsymbol{f}_j\Big).∂ct−n​∂ct​​≈diag(j=t−n+1∏t​fj​).

If a unit learns to keep fj,i≈1f_{j,i}\approx1fj,i​≈1 over the stretch where a dependency must be remembered, the gradient along that path neither shrinks nor grows: the error "rides the carousel". There is no weight matrix in this path, so there is no spectral radius to get wrong, and no activation derivative (the cell state is not squashed on the recurrent path). Information and gradient both have a highway.

The gate is a learned per-unit decay rate

For a constant forget value fff, a memory decays as fkf^{k}fk after kkk steps, a "half-life" of ln⁡0.5/ln⁡f\ln0.5/\ln fln0.5/lnf steps. With f=0.9f=0.9f=0.9 the half-life is 6.66.66.6 steps; with f=0.99f=0.99f=0.99 it is 696969 steps. The LSTM does not remove the exponential: it lets the network choose the base per unit and per time step, so different units can have different time scales, and the base can be set to almost exactly 1 when the content must be preserved.

What the "constant error carousel" does not promise

The diagonal direct path is only part of the Jacobian. The gates and candidate depend on ht−1\boldsymbol{h}_{t-1}ht−1​, and ht−1=ot−1⊙tanh⁡(ct−1)\boldsymbol{h}_{t-1}=\boldsymbol{o}_{t-1}\odot\tanh(\boldsymbol{c}_{t-1})ht−1​=ot−1​⊙tanh(ct−1​) depends on ct−1\boldsymbol{c}_{t-1}ct−1​, so there are additional paths through weight matrices; those paths can still vanish or explode, and gradient clipping remains standard for LSTMs. What the architecture guarantees is that a good path exists and that learning can find it by raising fff. LSTMs mitigate vanishing gradients; they do not abolish them, and in practice a vanilla LSTM still struggles to use context beyond a few hundred steps, which is part of why attention won.

Initialization: the forget-gate bias trick

At the default initialization, ft≈σ(0)=0.5f_t\approx\sigma(0)=0.5ft​≈σ(0)=0.5: the memory halves every step, so at initialization the LSTM has the same vanishing-gradient problem as the vanilla RNN, and long-range structure is learned only after the network has learned to open the forget gate. The remedy, advocated by Gers et al. (2000) and tested at scale by Jozefowicz, Zaremba and Sutskever (2015), is to initialize the forget-gate bias to a positive value (typically 1, sometimes 2 to 5 for very long dependencies) so that gates start mostly open. PyTorch does not do this for you; set it explicitly:

pythonlstm_forget_bias.py
import torch.nn as nn

lstm = nn.LSTM(input_size=32, hidden_size=64, num_layers=2, batch_first=True)
d = lstm.hidden_size
for name, p in lstm.named_parameters():
    if "bias" in name:
        # PyTorch stacks the gates in the order (input, forget, cell, output):
        # bias vector has length 4*d; the forget gate occupies [d : 2d].
        p.data.zero_()
        p.data[d:2 * d] = 1.0      # note: bias_ih and bias_hh are SUMMED, so total forget bias = 2.0 here
print(lstm.bias_ih_l0[d:2 * d].sum().item())   # 64.0

Both bias_ih and bias_hh contribute to the pre-activation, so setting both to 1 gives an effective forget bias of 2. That is fine, but know it is happening.

Bidirectional and stacked recurrent networks

Bidirectional RNNs (Schuster and Paliwal, 1997). A unidirectional RNN at position ttt has only seen x1:t\boldsymbol{x}_{1:t}x1:t​. Many tasks, such as tagging a word as a person's name, depend on the words after it too ("Washington was founded in..." versus "Washington said..."). A bidirectional RNN runs two independent recurrent networks, a forward one producing h→t\overrightarrow{\boldsymbol{h}}_tht​ from x1:t\boldsymbol{x}_{1:t}x1:t​ and a backward one producing h←t\overleftarrow{\boldsymbol{h}}_tht​ from xT:t\boldsymbol{x}_{T:t}xT:t​, and concatenates ht=[h→t;h←t]∈R2d\boldsymbol{h}_t=[\overrightarrow{\boldsymbol{h}}_t;\overleftarrow{\boldsymbol{h}}_t]\in\R^{2d}ht​=[ht​;ht​]∈R2d. Each position now has a summary of the full context. The cost is twice the parameters and compute.

The restriction to remember: a bidirectional model needs the whole input in advance. It is perfect for encoders (tagging, classification, the encoder of a translation model, the acoustic model in offline speech recognition) and impossible for autoregressive generation, where the future does not exist yet. Using a bidirectional layer in a next-token language model leaks the answer: the backward state at position ttt has already seen wt+1w_{t+1}wt+1​, the very token you are asked to predict, and your validation loss would look miraculous while the model is useless. This is the same issue that motivates masked language modeling in BERT (Week 10).

Stacked (deep) RNNs. The recurrence is already deep in time, but each step is a single shallow transformation. Stacking LLL layers (ht(ℓ)=cell(ℓ)(ht(ℓ−1),ht−1(ℓ))\boldsymbol{h}^{(\ell)}_t=\text{cell}^{(\ell)}(\boldsymbol{h}^{(\ell-1)}_t,\boldsymbol{h}^{(\ell)}_{t-1})ht(ℓ)​=cell(ℓ)(ht(ℓ−1)​,ht−1(ℓ)​)) adds depth in the feature direction, giving the model room for hierarchical processing: lower layers tend to capture local, syntactic structure and upper layers more abstract features. Two to four layers is typical for LSTM models (Google's 2016 neural translation system used eight, which required residual connections between layers to train). Beyond a couple of layers, add residual connections and dropout between layers (not on the recurrent connection, see the mistakes section).

In PyTorch both are arguments: nn.LSTM(m, d, num_layers=2, bidirectional=True, batch_first=True). The output has shape (B, T, 2*d), and h_n has shape (num_layers*2, B, d), ordered layer by layer with the forward direction first. To get the final forward and backward states of the top layer you take h_n[-2] and h_n[-1].

import torch
import torch.nn as nn

class BiLSTMTagger(nn.Module):
    """Per-token classifier: embeds tokens, runs a 2-layer BiLSTM, projects each position to tag logits."""
    def __init__(self, vocab_size, n_tags, emb=64, hid=128):
        super().__init__()
        self.emb = nn.Embedding(vocab_size, emb, padding_idx=0)
        self.rnn = nn.LSTM(emb, hid, num_layers=2, bidirectional=True, batch_first=True, dropout=0.3)
        self.out = nn.Linear(2 * hid, n_tags)

    def forward(self, tokens, lengths):
        x = self.emb(tokens)                                           # (B, T, emb)
        # Pack so the BACKWARD direction starts at each sequence's true last token, not at padding
        packed = nn.utils.rnn.pack_padded_sequence(x, lengths.cpu(), batch_first=True, enforce_sorted=False)
        packed_out, _ = self.rnn(packed)
        out, _ = nn.utils.rnn.pad_packed_sequence(packed_out, batch_first=True, total_length=tokens.size(1))
        return self.out(out)                                           # (B, T, n_tags)

model = BiLSTMTagger(vocab_size=1000, n_tags=9)
tokens = torch.randint(1, 1000, (3, 7)); tokens[1, 5:] = 0; tokens[2, 3:] = 0     # 0 = padding
lengths = torch.tensor([7, 5, 3])
logits = model(tokens, lengths)
print(logits.shape)    # torch.Size([3, 7, 9])

Padding deserves emphasis. If you batch sequences of different lengths by padding and run a bidirectional RNN naively, the backward direction starts by reading padding tokens, corrupting its state. pack_padded_sequence (or masking the loss and carefully gathering the last real state) fixes this. The rule: never take out[:, -1] as "the last hidden state" of a padded batch; index by lengths - 1, or use h_n.

Sequence-to-sequence learning

Machine translation breaks the aligned many-to-many assumption: "je suis étudiant" has three tokens, "I am a student" has four, and the word order may differ. The encoder-decoder (or seq2seq) architecture, introduced independently by Cho et al. (2014) and Sutskever, Vinyals and Le (2014), solves this by factoring the problem into two networks:

  1. The encoder RNN reads the source x1:S\boldsymbol{x}_{1:S}x1:S​ and compresses it into a representation (in the simplest version, its final hidden state hS\boldsymbol{h}_ShS​, the "context vector").
  2. The decoder RNN is an autoregressive language model over the target, conditioned on that context: p(y1:T∣x)=∏t=1Tp(yt∣y<t,x)p(y_{1:T}\mid\boldsymbol{x})=\prod_{t=1}^{T}p(y_t\mid y_{<t},\boldsymbol{x})p(y1:T​∣x)=∏t=1T​p(yt​∣y<t​,x). Its initial state is set from the encoder's summary.

Special tokens make this work. A <sos> (start) token seeds the decoder, and <eos> (end) is a vocabulary item the decoder learns to emit when it is done; that is how a variable-length output is produced. Training minimizes the cross-entropy summed over target positions, backpropagating through the decoder, into the encoder, and into the embeddings. Sutskever et al. (2014) used a 4-layer deep LSTM, and reported a striking trick: reversing the source sentence improved results, because it shortens the distance between the first source words and the first target words and hands the optimization many short-term dependencies.

The information bottleneck

The weakness is visible in the figure: everything the decoder knows about the source must pass through one fixed-size vector. Whether the source has 5 words or 50, the context is Rd\R^dRd with the same ddd. Cho et al. (2014, "On the properties of neural machine translation: encoder-decoder approaches") showed empirically that translation quality dropped sharply as the sentence length grew past those seen in training. This bottleneck is the problem attention solves, in the next-but-one section.

Teacher forcing and exposure bias

How do we feed the decoder during training? Two options at step ttt:

  • Teacher forcing: input the ground-truth previous token yt−1y_{t-1}yt−1​ regardless of what the model would have predicted.
  • Free running: input the model's own previous prediction y^t−1\hat y_{t-1}y^​t−1​.

Teacher forcing is the default, for good reasons. It makes every time step's loss independent of earlier predictions, so the whole target sequence can be processed in parallel for non-recurrent decoders, gradients are stable, and early training does not drown in garbage inputs. It also corresponds to maximizing the true likelihood ∏p(yt∣y<tgold,x)\prod p(y_t\mid y_{<t}^{\text{gold}},\boldsymbol{x})∏p(yt​∣y<tgold​,x).

The price is exposure bias (term from Ranzato et al., 2016): the model is trained only on gold prefixes, but at test time it conditions on its own, possibly erroneous, prefixes. One early mistake produces a prefix the model never saw in training, which raises the chance of a second mistake, and errors compound along the sequence. Train-test mismatch of this kind is a distribution shift of the decoder's inputs.

Mitigations, from simple to sophisticated:

  • Scheduled sampling (Bengio, Vinyals, Jaitly and Shazeer, 2015): with probability ϵk\epsilon_kϵk​ feed the model's own prediction instead of the gold token, and anneal ϵ\epsilonϵ from 0 (pure teacher forcing) upward over training. It is easy to implement but optimizes a slightly inconsistent objective.
  • Sequence-level training such as MIXER (Ranzato et al., 2016) or minimum risk training, which optimizes a sequence metric like BLEU via policy-gradient or sampling estimates; this is a precursor to RLHF-style ideas in Week 15.
  • Better decoding (beam search, next section) and larger models, which reduce the rate of first mistakes. In practice, modern Transformers trained with teacher forcing work extremely well, which suggests exposure bias is a manageable rather than fatal issue.

import random
import torch
import torch.nn as nn

class Decoder(nn.Module):
    def __init__(self, vocab, emb, hid):
        super().__init__()
        self.emb = nn.Embedding(vocab, emb)
        self.cell = nn.GRUCell(emb, hid)
        self.out = nn.Linear(hid, vocab)

    def forward(self, h, targets, sos_id, tf_ratio=1.0):
        """h: (B, hid) initial state from the encoder; targets: (B, T) gold tokens (incl. <eos>).
        tf_ratio = probability of feeding the gold token (1.0 = pure teacher forcing)."""
        B, T = targets.shape
        inp = torch.full((B,), sos_id, dtype=torch.long, device=targets.device)
        logits = []
        for t in range(T):
            h = self.cell(self.emb(inp), h)                      # (B, hid)
            step_logits = self.out(h)                            # (B, vocab)
            logits.append(step_logits)
            use_gold = random.random() < tf_ratio
            inp = targets[:, t] if use_gold else step_logits.argmax(dim=-1)   # next input
        return torch.stack(logits, dim=1)                        # (B, T, vocab)

dec = Decoder(vocab=20, emb=16, hid=32)
h0 = torch.zeros(5, 32)
tgt = torch.randint(3, 20, (5, 9))
logits = dec(h0, tgt, sos_id=1, tf_ratio=0.8)     # 80% teacher forcing, 20% self-feeding
loss = nn.functional.cross_entropy(logits.reshape(-1, 20), tgt.reshape(-1))
print(logits.shape, float(loss))

Decoding: greedy versus beam search

After training, we want the most probable output sequence y^=arg⁡max⁡y∑tlog⁡p(yt∣y<t,x)\hat y=\arg\max_y\sum_t\log p(y_t\mid y_{<t},\boldsymbol{x})y^​=argmaxy​∑t​logp(yt​∣y<t​,x). The number of candidate sequences is VTV^{T}VT, and because each factor depends on the previous choices the problem has no dynamic-programming shortcut for a recurrent decoder (the state depends on the entire prefix). We approximate.

Greedy decoding picks the argmax at every step. It is fast (O(T)O(T)O(T) model calls) but myopic: a locally best token can lead into a poor continuation, exactly as in the toy bigram example in the demo below, where the most probable first word leads to a flat, high-entropy continuation.

Beam search keeps the BBB best partial hypotheses (ranked by cumulative log-probability) at every step. At each step, every hypothesis is expanded by all VVV possible next tokens, giving BVBVBV candidates, and the top BBB are retained. Hypotheses that emit <eos> are moved to a finished list. The algorithm stops when no live hypotheses are left or a length limit is reached, and returns the finished hypothesis with the best (normalized) score. Cost is O(BTV)O(BTV)O(BTV) with batching across the beam; B=1B=1B=1 recovers greedy decoding.

Three practical details matter:

  1. Length bias. The score of a hypothesis is a sum of negative numbers, so every extra token lowers it, and beam search systematically prefers short outputs, including empty or truncated translations. The standard fix is length normalization: rank finished hypotheses by 1∣y∣α∑tlog⁡p(yt∣⋅)\frac{1}{|y|^{\alpha}}\sum_t\log p(y_t\mid\cdot)∣y∣α1​∑t​logp(yt​∣⋅) with α∈[0,1]\alpha\in[0,1]α∈[0,1] (α=1\alpha=1α=1 is the per-token mean). Google's NMT system (Wu et al., 2016) used a slightly different penalty, plus a coverage term.
  2. Larger beams are not monotonically better. More search finds higher-probability sequences, but the probability under the model is not the same as quality. Tuning shows BLEU for translation typically improves up to a beam of about 4 to 10 then flattens or even degrades; for open-ended generation (stories, chat), beam search yields bland, repetitive text, which is why sampling methods (top-kkk, nucleus sampling) are preferred there (Week 10).
  3. Beam search is a heuristic and can be wrong even for the model. It is not guaranteed to find the true argmax.

We measured how close beam search gets to the exact optimum. For 60 random bigram language models (vocabulary of 12 words, sequences of length 10, concentrated Dirichlet-distributed transition rows), the true best sequence can be found exactly with the Viterbi algorithm, so we can measure the gap in log-probability between that optimum and what beam search returns.

Greedy search misses the optimum in two of three cases and loses over a nat on average (a factor of e1.16≈3.2e^{1.16}\approx3.2e1.16≈3.2 in probability); a width of only 4 recovers most of the gap, and returns diminish quickly. pythonbeam_search.py
import math
from typing import Callable, List, Tuple

def beam_search(step: Callable[[List[int]], List[float]], sos: int, eos: int,
                beam: int = 4, max_len: int = 20, alpha: float = 0.7) -> List[Tuple[List[int], float]]:
    """step(prefix) returns log p(next token | prefix) as a list of length V.
    Returns finished hypotheses (token list without sos, normalized score), best first."""
    live = [([sos], 0.0)]                    # (prefix, cumulative log-prob)
    finished = []
    for _ in range(max_len):
        candidates = []
        for prefix, score in live:
            logp = step(prefix)
            for tok, lp in enumerate(logp):
                candidates.append((prefix + [tok], score + lp))
        candidates.sort(key=lambda c: c[1], reverse=True)
        live = []
        for prefix, score in candidates[: beam * 2]:           # look a little past `beam` so eos does not starve the beam
            if prefix[-1] == eos:
                length = len(prefix) - 1                         # exclude sos
                finished.append((prefix[1:], score / (length ** alpha)))
            else:
                live.append((prefix, score))
            if len(live) == beam:
                break
        if not live:
            break
    if not finished:                                             # fell off max_len: return the live ones
        finished = [(p[1:], s / (max(1, len(p) - 1) ** alpha)) for p, s in live]
    return sorted(finished, key=lambda f: f[1], reverse=True)

# Toy check: a 3-token vocabulary {0: <eos>, 1: a, 2: b}; model prefers 'a' then 'b' then stops
def toy_step(prefix):
    table = {1: [0.05, 0.05, 0.9], 2: [0.9, 0.05, 0.05]}         # after 'a' -> 'b'; after 'b' -> <eos>
    probs = table.get(prefix[-1], [0.1, 0.8, 0.1])               # after <sos> (=3) -> 'a'
    return [math.log(p) for p in probs]

print(beam_search(toy_step, sos=3, eos=0, beam=2, max_len=6))   # [([1, 2, 0], ...)]

Attention: removing the bottleneck

Squeezing a 50-word sentence into one vector and asking a decoder to unfold it is cruel. When a human translates, they glance back at the relevant source words for each target word. Attention lets the decoder do the same: at every output step it computes a weighted average of all encoder states, with weights that depend on what it is about to produce. Bahdanau, Cho and Bengio (2015, "Neural machine translation by jointly learning to align and translate") introduced this for translation; the idea of a learned soft alignment is the direct ancestor of the attention in Week 9.

Bahdanau (additive) attention

Let the encoder produce one annotation per source position, h1,…,hS\boldsymbol{h}_1,\dots,\boldsymbol{h}_Sh1​,…,hS​ (typically from a bidirectional RNN, so each hi∈R2d\boldsymbol{h}_i\in\R^{2d}hi​∈R2d summarizes the source around position iii). Let st−1\boldsymbol{s}_{t-1}st−1​ be the decoder state before producing output ttt. For each decoder step:

  1. Score how well each source position matches the current decoding need with a small feed-forward network: eti=v⊤tanh⁡ ⁣(Wst−1+Uhi),v∈Ra, W∈Ra×ds, U∈Ra×dh.e_{ti}=\boldsymbol{v}^\top\tanh\!\big(\mathbf{W}\boldsymbol{s}_{t-1}+\mathbf{U}\boldsymbol{h}_i\big),\qquad \boldsymbol{v}\in\R^{a},\ \mathbf{W}\in\R^{a\times d_s},\ \mathbf{U}\in\R^{a\times d_h}.eti​=v⊤tanh(Wst−1​+Uhi​),v∈Ra, W∈Ra×ds​, U∈Ra×dh​.

The key points are conceptual. The "alignment" is soft (a distribution, not a hard choice), which makes the whole mechanism differentiable: gradients flow from the loss through ct\boldsymbol{c}_tct​ into both the encoder states and the scoring network, and the alignment is learned without any alignment labels, purely from the translation loss. The context vector is different at every step: the fixed-size bottleneck is replaced by SSS vectors the decoder can address, so memory grows with the source length. And the weights are interpretable: plotting αti\alpha_{ti}αti​ as a matrix (target by source) shows what the model looked at, usually a near-diagonal band with local reorderings (adjective-noun swaps) that match linguistic intuition. Bahdanau et al. also reported that BLEU no longer collapsed for long sentences.

Gradient flow through attention

Attention also shortens gradient paths. Without it, the gradient from a target word to the first source word travels back through the decoder steps and then through all encoder steps, a path of length about S+TS+TS+T with the vanishing problems above. With attention, the loss at step ttt reaches hi\boldsymbol{h}_ihi​ in a single hop: ∂Lt/∂hi=αti ∂Lt/∂ct+(terms through αt⋅)\partial\mathcal{L}_t/\partial\boldsymbol{h}_i=\alpha_{ti}\,\partial\mathcal{L}_t/\partial\boldsymbol{c}_t+(\text{terms through }\alpha_{t\cdot})∂Lt​/∂hi​=αti​∂Lt​/∂ct​+(terms through αt⋅​). The distance between any target position and any source position is constant. That is a second reason attention works, beyond removing the capacity bottleneck, and it is the property the Transformer pushes to its logical extreme by making every position attend to every other.

Luong (multiplicative) attention and score functions

Luong, Pham and Manning (2015, "Effective approaches to attention-based neural machine translation") simplified and compared variants. Differences from Bahdanau's version:

  • Use the current decoder state st\boldsymbol{s}_tst​ (computed first, from the previous word and state) to attend, instead of st−1\boldsymbol{s}_{t-1}st−1​; then combine context and state: s~t=tanh⁡(Wc[ct;st])\tilde{\boldsymbol{s}}_t=\tanh(\mathbf{W}_c[\boldsymbol{c}_t;\boldsymbol{s}_t])s~t​=tanh(Wc​[ct​;st​]) and predict from s~t\tilde{\boldsymbol{s}}_ts~t​.
  • Cheaper score functions than the feed-forward network:

  • Input feeding. The previous attentional vector s~t−1\tilde{\boldsymbol{s}}_{t-1}s~t−1​ is concatenated to the next decoder input so the model knows what it already attended to (a soft coverage mechanism).

The Transformer adds 1/dk1/\sqrt{d_k}1/dk​​ scaling because dot products of high-dimensional vectors have variance growing with dkd_kdk​, which pushes the softmax into saturation (Week 9). Dot-product attention is faster and uses highly optimized matrix multiplication, at the price of requiring query and key to have the same dimension; additive attention can work in mismatched spaces and was found to be better for large ddd without scaling.

import torch
import torch.nn as nn
import torch.nn.functional as F

class AdditiveAttention(nn.Module):
    """Bahdanau: e_ti = v^T tanh(W s + U h_i)."""
    def __init__(self, dec_dim, enc_dim, att_dim):
        super().__init__()
        self.W = nn.Linear(dec_dim, att_dim, bias=False)
        self.U = nn.Linear(enc_dim, att_dim, bias=True)
        self.v = nn.Linear(att_dim, 1, bias=False)

    def forward(self, s, enc, mask):
        """s: (B, dec_dim) decoder state; enc: (B, S, enc_dim); mask: (B, S) True where real token."""
        scores = self.v(torch.tanh(self.W(s).unsqueeze(1) + self.U(enc))).squeeze(-1)   # (B, S)
        scores = scores.masked_fill(~mask, float("-inf"))                                # ignore padding
        alpha = F.softmax(scores, dim=-1)                                               # (B, S), rows sum to 1
        context = torch.bmm(alpha.unsqueeze(1), enc).squeeze(1)                          # (B, enc_dim)
        return context, alpha

class DotAttention(nn.Module):
    """Luong 'dot' (requires dec_dim == enc_dim) and 'general' (learned bilinear map) in one class."""
    def __init__(self, dec_dim, enc_dim, general=True):
        super().__init__()
        self.Wa = nn.Linear(enc_dim, dec_dim, bias=False) if general else nn.Identity()

    def forward(self, s, enc, mask):
        scores = torch.bmm(self.Wa(enc), s.unsqueeze(-1)).squeeze(-1)                   # (B, S)
        alpha = F.softmax(scores.masked_fill(~mask, float("-inf")), dim=-1)
        return torch.bmm(alpha.unsqueeze(1), enc).squeeze(1), alpha

From alignment to attention to Transformers

Soft alignment had precedent in statistical MT, where IBM alignment models (1990s) estimated which source word generated which target word. Bahdanau et al. (arXiv 2014, ICLR 2015) learned alignment jointly with translation. Luong et al. (EMNLP 2015) simplified it. Xu et al. (2015, "Show, attend and tell") applied the same mechanism over image regions for captioning. Google's neural machine translation system (Wu et al., 2016) put an attentional LSTM seq2seq into production. In 2017, Vaswani et al. asked whether the recurrence was needed at all, and the answer ("Attention is all you need") is the subject of Week 9.

Applications

Machine translation

Neural machine translation was the application that drove this whole line of work. The pipeline: tokenize the source and target (subword units, see Week 8), embed, encode with a (bi)LSTM, decode with an attentional LSTM, and search with beam search. The 2014 to 2016 sequence of results is a good case study in how quickly the field moved. Sutskever et al. (2014) showed a plain LSTM seq2seq could approach phrase-based statistical MT on English to French; attention (Bahdanau 2015, Luong 2015) removed the length degradation; and Wu et al. (2016) deployed an eight-layer attentional LSTM with residual connections as Google Translate's production system, reporting large human-evaluated error reductions on several language pairs. The metric to know is BLEU: a geometric mean of nnn-gram precisions (n=1..4n=1..4n=1..4) against reference translations, multiplied by a brevity penalty that punishes outputs shorter than the reference. It is cheap, correlates only roughly with human judgment, and is only comparable when computed with the same tokenization and tooling (use sacreBLEU).

Speech recognition and CTC

In speech recognition, the input is a sequence of TTT acoustic frames (typically 100 per second of audio, as log-mel filterbank features) and the output is a shorter character or word-piece sequence. Alignment between frames and letters is unknown. Attention-based seq2seq models can learn it (Chan et al. 2016, "Listen, attend and spell"), but a different loss, connectionist temporal classification (Graves, Fernandez, Gomez and Schmidhuber, 2006), is widely used because it needs no decoder at all and supports streaming.

The idea: let a (bi)RNN emit, at every frame, a distribution over the output alphabet plus a special blank symbol ∅\varnothing∅. A frame-level labeling π∈(A∪{∅})T\pi\in(\mathcal{A}\cup\{\varnothing\})^{T}π∈(A∪{∅})T is mapped to an output string by the many-to-one function B\mathcal{B}B that first merges repeated symbols and then deletes blanks: B(h h ∅ e l ∅ l l o)=hello\mathcal{B}(\text{h h }\varnothing\text{ e l }\varnothing\text{ l l o})=\text{hello}B(h h ∅ e l ∅ l l o)=hello. (The blank between the two "l"s is what allows double letters.) The probability of a target string y\boldsymbol{y}y is the sum over all frame-level paths that collapse to it, assuming frame-wise conditional independence given the input:

p(y∣x)=∑π: B(π)=y ∏t=1Tp(πt∣x).p(\boldsymbol{y}\mid\boldsymbol{x})=\sum_{\pi:\ \mathcal{B}(\pi)=\boldsymbol{y}}\ \prod_{t=1}^{T}p(\pi_t\mid\boldsymbol{x}).p(y∣x)=π: B(π)=y∑​ t=1∏T​p(πt​∣x).

The number of paths is exponential, but a forward dynamic program over the target string interleaved with blanks computes the sum in O(T⋅∣y∣)O(T\cdot|\boldsymbol{y}|)O(T⋅∣y∣), and its gradient comes from the matching backward pass, so the loss −log⁡p(y∣x)-\log p(\boldsymbol{y}\mid\boldsymbol{x})−logp(y∣x) is trained end to end. At test time one can decode greedily (argmax per frame, then collapse) or with a beam search that merges paths with equal collapsed prefixes. CTC is the same marginalization idea as the latent-variable models of Week 12, applied to alignments.

Time-series forecasting

Forecasting is a many-to-one or many-to-many problem on real-valued sequences: given the past LLL observations (a window), predict the next HHH values. Recurrent networks were the neural baseline for years, with caveats that experienced practitioners repeat constantly:

  • Always compare with simple baselines. A "predict the last value" or "same value as one season ago" baseline is shockingly hard to beat for many series. Report MAE or RMSE relative to the baseline, not in isolation.
  • Split by time, never randomly. A random train/validation split lets the model interpolate between neighbouring windows it has trained on and gives dishonestly good numbers. Train on the past, validate on a later period, test on the latest.
  • Normalize using training statistics only, and consider per-window normalization (subtract the window's last value or mean) for non-stationary series.
  • Choose between one-step-ahead recursion and direct multi-horizon output. Feeding predictions back (recursive forecasting) has the same exposure-bias issue as seq2seq decoding; predicting all HHH steps at once avoids it at the cost of ignoring dependencies between outputs.

import numpy as np
import torch
import torch.nn as nn

def windows(s):

    Y = np.stack([s[i + L:i + L + H] for i in range(len(s) - L - H)])

        self.head = nn.Linear(hid, horizon)            # direct multi-horizon: all H steps at once
    def forward(self, x):
        out, _ = self.rnn(x)
        return self.head(out[:, -1])                    # last hidden state -> (B, H)

        nn.utils.clip_grad_norm_(model.parameters(), 1.0); opt.step()

One-dimensional convolutions and temporal convolutional networks

Recurrence is not the only way to process a sequence. A 1D convolution slides a kernel of width kkk along the time axis: yt=∑j=0k−1Wjxt−j\boldsymbol{y}_t=\sum_{j=0}^{k-1}\mathbf{W}_j\boldsymbol{x}_{t-j}yt​=∑j=0k−1​Wj​xt−j​, exactly the operation of Week 5 with one spatial dimension. Compared with an RNN it has three advantages: all positions are computed in parallel (no sequential dependency), gradients travel along paths whose length is the network depth, not the sequence length, and training is stable because there is no repeated multiplication by the same matrix. The disadvantage is a fixed, finite receptive field: a stack of LLL layers with kernel kkk sees only 1+L(k−1)1+L(k-1)1+L(k−1) steps.

Causal convolutions pad on the left only, so yt\boldsymbol{y}_tyt​ never depends on xt+1,…\boldsymbol{x}_{t+1},\dotsxt+1​,… (necessary for forecasting and autoregressive generation). Dilated convolutions skip inputs: with dilation δ\deltaδ, taps are spaced δ\deltaδ apart, yt=∑jWjxt−δj\boldsymbol{y}_t=\sum_j\mathbf{W}_j\boldsymbol{x}_{t-\delta j}yt​=∑j​Wj​xt−δj​. Doubling the dilation at each layer (δ=1,2,4,…,2L−1\delta=1,2,4,\dots,2^{L-1}δ=1,2,4,…,2L−1) makes the receptive field grow exponentially with depth, 1+(k−1)(2L−1)1+(k-1)(2^{L}-1)1+(k−1)(2L−1), at constant cost per layer.

WaveNet (van den Oord et al., 2016) used this stack for raw audio generation at 16 kHz, and Bai, Kolter and Koltun (2018, "An empirical evaluation of generic convolutional and recurrent networks for sequence modeling") packaged residual blocks of dilated causal convolutions as the temporal convolutional network (TCN) and showed that it matched or beat LSTMs on a range of standard sequence benchmarks, with faster training and longer effective memory. The lesson is nuanced: for fixed-horizon tasks where you can afford a receptive field covering the relevant history, TCNs are a strong, simple baseline; RNNs retain the advantage of constant memory at inference and unbounded (if fragile) context.

import torch
import torch.nn as nn
import torch.nn.functional as F

class CausalConv1d(nn.Module):
    """Conv1d that only looks at the past: pad (k-1)*dilation zeros on the LEFT."""
    def __init__(self, c_in, c_out, k, dilation):
        super().__init__()
        self.pad = (k - 1) * dilation
        self.conv = nn.Conv1d(c_in, c_out, k, dilation=dilation)
    def forward(self, x):                               # x: (B, C, T)
        return self.conv(F.pad(x, (self.pad, 0)))       # output length stays T

class TCNBlock(nn.Module):
    def __init__(self, c, k, dilation, p=0.1):
        super().__init__()
        self.c1, self.c2 = CausalConv1d(c, c, k, dilation), CausalConv1d(c, c, k, dilation)
        self.drop = nn.Dropout(p)
    def forward(self, x):
        y = self.drop(F.relu(self.c1(x)))
        y = self.drop(F.relu(self.c2(y)))
        return F.relu(x + y)                            # residual connection

class TCN(nn.Module):
    def __init__(self, c_in, c_hidden, n_layers=6, k=3):
        super().__init__()
        self.inp = nn.Conv1d(c_in, c_hidden, 1)
        self.blocks = nn.Sequential(*[TCNBlock(c_hidden, k, 2 ** i) for i in range(n_layers)])
    def forward(self, x):                               # (B, C_in, T) -> (B, C_hidden, T)
        return self.blocks(self.inp(x))

net = TCN(c_in=1, c_hidden=32, n_layers=6, k=3)
x = torch.randn(4, 1, 200)
print(net(x).shape)                                      # (4, 32, 200)

How this fits the bigger picture

Three families compete for sequence modeling: recurrent (constant memory, sequential), convolutional (parallel, finite receptive field), and attention-based (parallel, global receptive field, quadratic cost in length). Weeks 9 to 11 show attention overtaking the other two for most tasks at scale, but recurrent ideas are alive again in state-space models such as S4 and Mamba (see Week 16) that revive linear recurrences with careful parameterization to avoid the vanishing-gradient pitfall derived above.

pythonlab1_model.py
import torch, torch.nn as nn

class CharRNN(nn.Module):
    def __init__(self, V, emb=64, hid=512, layers=2, cell="lstm", dropout=0.2):
        super().__init__()
        self.emb = nn.Embedding(V, emb)
        rnn_cls = {"lstm": nn.LSTM, "gru": nn.GRU}[cell]
        self.rnn = rnn_cls(emb, hid, num_layers=layers, batch_first=True, dropout=dropout)
        self.drop = nn.Dropout(dropout)
        self.head = nn.Linear(hid, V)
        self.hid, self.layers, self.cell = hid, layers, cell

    def forward(self, x, state=None):                 # x: (B, K) int64
        out, state = self.rnn(self.drop(self.emb(x)), state)    # out: (B, K, hid)
        return self.head(self.drop(out)), state       # logits: (B, K, V)

    def init_state(self, B, device):
        h = torch.zeros(self.layers, B, self.hid, device=device)
        return (h, h.clone()) if self.cell == "lstm" else h

def detach(state):
    """Cut the graph at the chunk boundary (truncated BPTT). Handles LSTM tuples and GRU tensors."""
    return tuple(s.detach() for s in state) if isinstance(state, tuple) else state.detach()

Step 3: training and evaluation. The BPC is the cross-entropy in nats divided by ln⁡2\ln2ln2.

pythonlab1_train.py
import time, math
import torch, torch.nn as nn

def evaluate(model, src, K):
    model.eval()
    state, total, count = model.init_state(src.size(0), src.device), 0.0, 0
    with torch.no_grad():
        for i in range(0, src.size(1) - 1, K):
            x, y = get_chunk(src, i, K)
            logits, state = model(x, state)
            total += nn.functional.cross_entropy(logits.reshape(-1, logits.size(-1)), y.reshape(-1), reduction="sum").item()
            count += y.numel()
    nats = total / count
    return nats, nats / math.log(2), math.exp(nats)        # loss, bits per char, perplexity

def train(cell="lstm", epochs=5, lr=2e-3, clip=1.0):
    torch.manual_seed(0)
    model = CharRNN(V, cell=cell).to(device)
    # forget-gate bias trick for the LSTM (see the LSTM section)
    if cell == "lstm":
        for name, p in model.rnn.named_parameters():
            if "bias_ih" in name:
                p.data[model.hid : 2 * model.hid] = 1.0
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    sched = torch.optim.lr_scheduler.CosineAnnealingLR(opt, T_max=epochs * (train_b.size(1) // K))
    for ep in range(epochs):
        model.train(); t0 = time.time()
        state = model.init_state(B, device)
        for i in range(0, train_b.size(1) - 1, K):
            x, y = get_chunk(train_b, i, K)
            state = detach(state)                             # carry state, cut gradients
            logits, state = model(x, state)
            loss = nn.functional.cross_entropy(logits.reshape(-1, V), y.reshape(-1))
            opt.zero_grad(set_to_none=True)
            loss.backward()
            gnorm = nn.utils.clip_grad_norm_(model.parameters(), clip)
            opt.step(); sched.step()
        _, bpc, ppl = evaluate(model, val_b, K)
        print(f"{cell} epoch {ep+1}  train loss {loss.item():.3f}  val BPC {bpc:.3f}  val ppl {ppl:.2f}  "
              f"last |grad| {gnorm:.2f}  {time.time()-t0:.0f}s")
    return model

lstm_model = train("lstm")
gru_model = train("gru")

Lab 2: sequence-to-sequence with attention on a toy translation task

Real translation needs data and hours of GPU time. To see every mechanism in minutes, we invent a toy language pair whose structure is known: the source is a random string of 6 to 8 letters from an alphabet of 12 symbols; the target is the reversed string with each letter mapped through a fixed substitution cipher. The correct alignment is therefore the anti-diagonal. A model without attention must squeeze the whole string into one vector; a model with attention should recover the anti-diagonal in its attention map, which gives us a ground truth to compare against, something real translation never offers.

Step 2: the model. A bidirectional GRU encoder, additive attention, and a GRU-cell decoder that, at each step, attends with its previous state, concatenates the context to the input embedding and predicts from state plus context.

pythonlab2_model.py
import random
import torch, torch.nn as nn, torch.nn.functional as F

class Encoder(nn.Module):
    def __init__(self, V, emb, hid):
        super().__init__()
        self.emb = nn.Embedding(V, emb, padding_idx=PAD)
        self.rnn = nn.GRU(emb, hid, batch_first=True, bidirectional=True)
        self.bridge = nn.Linear(2 * hid, hid)           # maps final fwd+bwd states to decoder's initial state
    def forward(self, src):
        out, h_n = self.rnn(self.emb(src))              # out: (B, S, 2*hid); h_n: (2, B, hid)
        h0 = torch.tanh(self.bridge(torch.cat([h_n[0], h_n[1]], dim=-1)))   # (B, hid)
        return out, h0

class AttnDecoder(nn.Module):
    def __init__(self, V, emb, hid, enc_dim, att=64, use_attention=True):
        super().__init__()
        self.emb = nn.Embedding(V, emb, padding_idx=PAD)
        self.use_attention = use_attention
        self.W, self.U, self.v = nn.Linear(hid, att, bias=False), nn.Linear(enc_dim, att), nn.Linear(att, 1, bias=False)
        self.cell = nn.GRUCell(emb + (enc_dim if use_attention else 0), hid)
        self.out = nn.Linear(hid + (enc_dim if use_attention else 0), V)

    def step(self, tok, h, enc, mask):
        e = self.emb(tok)                                                      # (B, emb)
        alpha = None
        if self.use_attention:
            scores = self.v(torch.tanh(self.W(h).unsqueeze(1) + self.U(enc))).squeeze(-1)     # (B, S)
            alpha = F.softmax(scores.masked_fill(~mask, float("-inf")), dim=-1)
            ctx = torch.bmm(alpha.unsqueeze(1), enc).squeeze(1)                               # (B, enc_dim)
            h = self.cell(torch.cat([e, ctx], dim=-1), h)
            logits = self.out(torch.cat([h, ctx], dim=-1))
        else:
            h = self.cell(e, h)
            logits = self.out(h)
        return logits, h, alpha

class Seq2Seq(nn.Module):
    def __init__(self, use_attention=True, emb=32, hid=128):
        super().__init__()
        self.enc = Encoder(len(src_vocab), emb, hid)
        self.dec = AttnDecoder(len(tgt_vocab), emb, hid, 2 * hid, use_attention=use_attention)

    def forward(self, src, tgt, tf=1.0):
        enc, h = self.enc(src)
        mask = src != PAD
        tok = torch.full((src.size(0),), SOS, dtype=torch.long)
        logits = []
        for t in range(tgt.size(1)):
            lg, h, _ = self.dec.step(tok, h, enc, mask)
            logits.append(lg)
            tok = tgt[:, t] if random.random() < tf else lg.argmax(-1)       # teacher forcing / scheduled sampling
        return torch.stack(logits, dim=1)                                      # (B, T, V_tgt)

    @torch.no_grad()
    def greedy(self, src, max_len=9):
        enc, h = self.enc(src); mask = src != PAD
        tok = torch.full((src.size(0),), SOS, dtype=torch.long)
        outs, atts = [], []
        for _ in range(max_len):
            lg, h, a = self.dec.step(tok, h, enc, mask)
            tok = lg.argmax(-1); outs.append(tok); atts.append(a)
        return torch.stack(outs, 1), (torch.stack(atts, 1) if atts[0] is not None else None)   # (B, T), (B, T, S)

        L = int((t == EOS).nonzero()[0]) + 1
        ok += int(torch.equal(p[:L], t[:L]))

Recurrent models fail in characteristic ways. This table maps symptoms to the usual cause and the fix; most of them cost somebody a weekend.

Symptom Likely cause Fix
Loss is nan after a few hundred steps, or spikes by orders of magnitude Exploding gradients through time (spectral radius of the recurrent Jacobian above 1) clip_grad_norm_ with a global threshold (0.5 to 5), lower the learning rate, check the orthogonal or identity-like initialization of Whh\mathbf{W}_{hh}Whh​
Loss plateaus at roughly ln⁡V\ln VlnV (the unigram or uniform level) and never moves Vanishing gradients, or a data bug (inputs and targets not shifted by one) Print one decoded (input, target) pair; switch to LSTM/GRU, set the forget-gate bias to 1, shorten the BPTT window while debugging
Train loss very low, val loss poor in a language model Hidden state carried across the train/val boundary, or overlap between train and val text Re-initialize state at the start of evaluation; split the corpus by contiguous chunk, not by random window
Training loss is excellent under teacher forcing but free-running samples are repetitive or drift Exposure bias Scheduled sampling, lower decoding temperature, beam search with a length penalty, or more data; always report metrics from free-running decoding
Padding tokens change the result, or batch size changes the output Padding is processed as real input, or loss is averaged over pad positions Use pack_padded_sequence (or a mask), ignore_index=PAD in the loss, and take the hidden state at the true last position

A short debugging routine that works on almost every sequence model:

  1. Overfit ten examples. If a model cannot drive the loss to near zero on ten sequences, there is a bug (shapes, shifts, masks, learning rate), not a capacity problem.
  2. Check the initial loss. It should be close to ln⁡V\ln VlnV for a vocabulary of size VVV (for V=65V=65V=65 characters, about 4.17). A very different value points at a wrong output scale or a wrong loss reduction.
  3. Log the gradient norm before clipping, every step. A norm that is nearly always above the clip threshold means the threshold is acting as the learning rate; a norm of about 10−610^{-6}10−6 means vanishing.
  4. Look at outputs, not only the loss. Sample text, print the greedy decode, plot the attention matrix.
  5. Test causality and masking explicitly (perturb the future, perturb the padding) as in the TCN code above.

Exercise 3: Why clipping by norm and not by value?

Explain the difference between clip_grad_value_ and clip_grad_norm_ for a gradient g=(30, 0.3)\boldsymbol{g}=(30,\,0.3)g=(30,0.3) and a threshold of 1. Which preserves the update direction?

Solution

Value clipping clamps each coordinate: (1, 0.3)(1,\,0.3)(1,0.3). The direction changed from almost exactly the first axis (angle ≈0.6∘\approx0.6^\circ≈0.6∘) to about 17∘17^\circ17∘ away from it, so the small coordinate now has a disproportionate influence. Norm clipping rescales the whole vector by 1/∥g∥≈1/301/\lVert\boldsymbol{g}\rVert\approx1/301/∥g∥≈1/30: (0.9999, 0.01)(0.9999,\,0.01)(0.9999,0.01), which has the same direction and a norm of 1. Exercise 6: Implement truncated BPTT correctly

The loop below has a bug that causes Trying to backward through the graph a second time. Find it and fix it. Also say what happens to the gradient across chunk boundaries after your fix.

python
h = torch.zeros(1, B, H)
for x, y in chunks:                 # each chunk: (B, 35)
    out, h = rnn(x, h)
    loss = criterion(head(out).reshape(-1, V), y.reshape(-1))
    opt.zero_grad(); loss.backward(); opt.step()
Solution

h returned by one chunk is still attached to that chunk's graph, which backward() has already freed. Fix: out, h = rnn(x, h.detach()) (or h = h.detach() right after the step). After the fix the hidden state value carries forward, so the model can use context from earlier chunks at inference-like behavior, but gradients do not flow across chunk boundaries: the effective gradient horizon is the chunk length (35), while the state's memory can still be longer. For an LSTM, detach both elements of the (h, c) tuple, for example h = tuple(s.detach() for s in h).

Exercise 10: Sequence labelling choice

For each task say whether you would use a unidirectional or bidirectional recurrent model, and which of many-to-one, many-to-many aligned, or encoder-decoder fits: (a) named entity recognition, (b) next-keystroke prediction on a phone, (c) sentiment of a movie review, (d) translating French to English, (e) transcribing speech with CTC.

Solution

(a) Bidirectional, many-to-many aligned: the label of a word depends on both sides. (b) Unidirectional, autoregressive: only the past is available at prediction time. Key takeaways

Key takeaways
  • A recurrent network applies the same cell at every step, carrying a state; unrolled, it is a deep network whose depth is the sequence length and whose layers share weights. BPTT is ordinary backprop on that graph, with gradients summed over time into the shared parameters.
  • The gradient to a state kkk steps back is a product of kkk Jacobians; its size is governed by the spectral radius of DWhh\mathbf{D}\mathbf{W}_{hh}DWhh​. Below 1 it vanishes (no long-range learning), above 1 it explodes. Clipping handles explosion; architecture handles vanishing.
  • LSTM and GRU use additive, gated updates of the state so that the Jacobian along the memory path is a learned diagonal near 1 rather than a repeated dense matrix. Initialize the LSTM forget-gate bias to about 1.
  • Truncated BPTT bounds memory and compute by detaching the state between chunks; the state carries forward but the gradient horizon is the chunk.
  • Bidirectional and stacked RNNs enrich representations but a bidirectional model cannot be used to generate or to train a next-token objective.
  • Seq2seq trains with teacher forcing and tests with self-feeding, which causes exposure bias; decode with beam search plus length normalization, and evaluate with free-running outputs.
  • A single fixed vector is a bottleneck. Attention computes a weighted average of all encoder states with data-dependent weights, giving a short gradient path and an interpretable soft alignment. Bahdanau uses an additive MLP score, Luong a multiplicative one.
  • 1D and temporal convolutions are parallel, stable alternatives with a receptive field that grows linearly (or exponentially with dilation); the next step, attention without recurrence, is Week 9.
