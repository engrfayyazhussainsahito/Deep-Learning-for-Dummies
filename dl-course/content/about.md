## What this course is {#what}

This is a free, open-source, 18-week deep learning course at the master's level. It is designed so that a motivated student can learn the material from the pages alone: every week moves from intuition, to mathematics, to code, to pitfalls, with figures, interactive demos, worked derivations, exercises with solutions, labs, and a reading list. It assumes calculus, linear algebra, probability, and programming experience in Python.

The course runs from foundations (tensors, backpropagation, optimization, regularization), through core architectures (convolutional, recurrent, attention-based), pretrained and generative models (language models, vision-language models, VAEs, GANs, diffusion), to advanced topics (graph networks, reinforcement learning, efficiency, trustworthy deep learning) and a final project. Start from the [syllabus](syllabus.html), which has the weekly schedule, grading and policies, and use the [glossary](glossary.html) as a quick reference.

## Build the site locally {#build}

The site is a static site generated by a small Node.js script. You need Node.js (a current long-term-support version) and npm.

```bash
npm install          # install the build dependencies
node build.js        # render every page into the site/ folder
```

Then open `site/index.html` directly in your browser, or serve the folder so that all features work consistently:

```bash
cd site
python3 -m http.server 8000     # then visit http://localhost:8000
```

To check a single week while you write, run `node build.js --check=N` (for example `--check=5`). It renders only that week without writing files and prints statistics and warnings (math errors, missing figures or demos, malformed charts, Python syntax errors, unclosed callouts). Fix all warnings before you submit a change.

## Deploy {#deploy}

The output in `site/` is plain HTML, CSS, and JavaScript, so any static host works.

- **GitHub Pages:** push the repository, build in a GitHub Actions workflow (`npm install` then `node build.js`), and publish the `site/` folder, or commit the built folder to a `gh-pages` branch.
- **Netlify or similar:** set the build command to `npm install && node build.js` and the publish directory to `site`.
- **Any static host or web server:** copy the contents of `site/` to the web root.

All paths between pages are relative, so the site also works when it is served from a sub-path such as `https://user.github.io/dl-course/`.

## Repository layout {#layout}

| Path | Contents |
| --- | --- |
| `content/` | One Markdown file per page: `week-01.md` to `week-18.md`, `syllabus.md`, `glossary.md`, `about.md` |
| `figures/` | SVG diagrams, named `weekNN-name.svg`, theme-aware (they use CSS classes instead of fixed colors) |
| `demos/` | Interactive demos, one JavaScript file per demo, named `weekNN-name.js` |
| `src/` | Page templates, styles, and the browser-side helper library (`src/assets/dl-lib.js`) |
| `build.js` | The static site generator |
| `SPEC.md` | The authoring specification: file formats, callouts, figures, charts, demos, code rules and the quality bar |
| `site/` | The generated output (do not edit by hand) |

Pages are written in Markdown with a few extensions: LaTeX math (KaTeX), callout blocks (`:::key`, `:::exercise`, `:::details` and others), figure and demo embeds, and chart blocks defined as JSON. Read `SPEC.md` before writing content.

## How to contribute {#contribute}

Contributions of every size are welcome.

- **Typos, errors and unclear passages.** Fix them directly and open a pull request, or open an issue that quotes the passage and says what is wrong. Technical errors (a wrong equation, a shape mismatch, a mis-cited paper) are the most valuable reports.
- **New exercises.** Add exercises with complete, checked solutions to the relevant week, following the `:::exercise` and `:::details Solution` pattern. Mix derivation, coding, and "what would happen if" questions.
- **Translations.** Translate a page into another language in a parallel directory and keep the math, code, and figure names unchanged. Open an issue first so the work is not duplicated.
- **New demos.** Follow the demo rules in `SPEC.md`: a single self-contained file that registers itself with `DL.register`, uses theme-aware colors from `DL.colors()`, handles resizing, pauses animations when off-screen, has labelled controls and a readout, and does not throw on extreme slider values. Test the numerical logic.
- **New figures.** SVG with a `viewBox`, no fixed colors, no scripts, legible at phone width.
- **Review.** Read a week as a student would and report what you got stuck on.

Before you open a pull request: run `node build.js --check=N` for each week you touched and confirm there are no warnings; write in your own words (do not copy text from books or papers); verify every citation (authors, title, year, venue); avoid em dashes; and disclose any use of AI assistants. Keep each pull request focused on one change.
